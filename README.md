# 航天器供电故障树 · 最小割集审计页

纯浏览器运行的 TypeScript + React 单页应用：对共享故障树（有向无环图）精确展开
**包含极小割集**，合并重复集合、按吸收律消去所有真超集，按事件标识排序输出顶事件割集，
并把基本事件归为 **必现 / 可选 / 无关**。在完整定性结论之上还提供
**独立失效概率的定量复核**：精确计算顶事件概率与逐事件干预条件概率。

- 无业务后端、无任何在线调用：构建产物为纯静态文件（React/Vite 本地打包，无 CDN）。
- 静态 Web 由 Dockerfile 多阶段构建（nginx 托管），通过 Docker Compose 发布。
- 宿主机端口可通过 `WEB_PORT` 配置；提供 `/healthz` HTTP 健康检查。
- Compose 中名为 `verify` 的一次性服务执行：代码测试 → 构建检查 → 规定场景断言 → HTTP 冒烟，
  完成后自行退出，并用退出码报告结果。

## 输入语法

基本事件（2–30 个，每行一个唯一 ASCII 标识，`#` 起始为注释）。
标识后可选第二字段填写该事件的**独立失效概率**（0–1 的十进制数，至多六位小数）：

```
BUS_FAULT            # 仅标识（旧格式）：完成全部定性审计，定量结论待补充
MAIN_SRC   0.01      # 标识 + 概率
COMMON     0.001     # 公用控制单元失效（两路共享单点）
```

概率规则：

- 接受 `0`、`1`、`0.5`、`.5`、`0.500000`、`1.000000`；
- 拒绝越界值、负号/正号、科学计数法、多余前导零（如 `01`）、空小数（`0.`）与超过六位小数；
- **概率缺失或非法不影响定性分析**：割集与归属照常给出，原文保留在编辑器中并可点击定位，
  仅定量结论被阻止；任一修正后立即恢复。

门（1–80 个，每行：`名称 AND|OR 输入...`，输入可为基本事件或其他门）：

```
LOSS   OR  COMMON_CTRL BUS_FAULT
MAINF  AND OR_MAIN LOSS
TOP    AND MAINF BKF
```

顶事件：单个门名称。

## 语义说明

- **AND 门**的割集：从每个输入的割集中各取一个并做并集（合取）。
- **OR 门**的割集：所有输入割集的并集（析取）。
- 规范化结果合并重复集合，并删除所有真超集（吸收律：`{A}` 吸收 `{A,B}`）。
- 共享子门经记忆化**仅规范化一次**，不随路径重复计算；事件归属基于顶事件最终割集：
  - 必现：出现在**每个**最小割集中（所有割集的交集）；
  - 可选：出现在部分割集中（并集减交集）；
  - 无关：不出现在任何割集中。

## 非法输入与定位

非法输入会原样保留在编辑器中，不被清空或改写。系统一次性诊断并支持点击定位：

- 非法 / 重复标识、数量越界、门语法或类型错误；
- 缺失引用（目标既非基本事件也非门）；
- 自引用（门直接引用自己）；
- 任意长度的环（Tarjan 强连通分量，给出具体环路径）；
- 顶事件不是已定义的门、门名与事件同名冲突。

## 复杂度上限（complexity_limit）

**任一门在其最终规范化族**上产生超过 2000 个最小割集时，结果状态为 `complexity_limit`，
并定位到首个超限的门（名称 + 行号）。此时**不会**输出顶事件割集或事件归属——
因为截断结果可能遗漏更小的解释，不允许冒充完整结论。

上限只对门的**最终**极小族判定：即使展开中途的原始组合数巨大（如与“全集”单割集
相并后坍缩为 1 个割集），只要最终族 ≤ 2000 仍给出完整结果。

## 定量复核（独立失效概率）

最小割集之间通常**共享基本事件**，既不穷尽也不互斥——把各割集概率直接相加会重复计算
交集。因此仅当**定性分析完整且全部基本事件的概率都有效**时才给出定量结论，且：

- 顶事件被建模为“各最小割集（合取）之析取”的单调布尔函数，假设基本事件相互独立；
- 采用 **Shannon 分解** `F = (1−p_i)·F|e_i=0 + p_i·F|e_i=1` 递归精确求值，
  配合记忆化共享所有中间状态与确定性变量次序，重叠割集按容斥语义被正确处理；
- 全部使用 **BigInt 精确有理算术**：输入为至多六位小数（n/10⁶），归约后分母只含
  因子 2、5，故每个结果都有**有限且精确的十进制表示**，无浮点舍入；
- 对每个事件同时给出：
  - 原概率 `p`；
  - 强制该事件**未发生**后的条件概率 `P(T|e=0)`；
  - 强制该事件**已发生**后的条件概率 `P(T|e=1)`；
  - 差值 `Δ = P(T|e=1) − P(T|e=0)`；
  - 两条可核对的一致关系：
    全概率分解 `P(T) = (1−p)·P(T|e=0) + p·P(T|e=1)`（精确相等），
    以及偏序 `P(T|e=0) ≤ P(T) ≤ P(T|e=1)`。
- 在归属表或定量表中**点选任一事件**，割集列表即时高亮所有包含该事件的最小割集
  （受其影响的解释），其余割集变暗，并显示该事件的干预核对面板。
- 概率为 `0` 或 `1` 时走确定性分支剪枝：条件概率仍有定义（如 `p=1` 时 `P(T)=P(T|e=1)`）。

### quantitative_limit

精确求值的不同状态数存在**确定性资源上限**（200000 个状态，固定且可复现）。
当割集高度重叠、精确展开超过该上限时，结果状态为 `quantitative_limit`：

- 页面显示 `quantitative_limit` 与已用状态数；
- **不输出任何概率**（包括顶事件概率），避免展示未经完整求值的部分结果；
- **定性最小割集与事件归属完整保留**；
- 修改输入（降低规模，或把概率改为 `0`/`1` 引入确定性剪枝）后定量结果立即恢复。

内置“压力示例”按钮可一键复现：30 个事件、80 个门、78 个十元高重叠割集
（另含必现事件 M），全部概率 0.5 时确定触发上限；“概率全 0”同构示例随即恢复。

## Docker Compose

```bash

WEB_PORT=9090 docker compose up -d --build web
# 或复制 .env.example 为 .env 后修改 WEB_PORT

curl -s http://localhost:8080/healthz   # => ok
```

### verify 一次性服务

```bash
docker compose run --build verify
# 等价地：docker compose up --build verify（web 健康后才执行）
```

`verify` 服务内的 `scripts/verify.sh` 依次执行：

1. `npm test` 代码测试；
2. `npm run build` 构建检查（tsc + vite build）；
3. `scripts/verify-scenarios.ts` 规定场景断言：
   - 吸收律：`A∨B∨(A∧B)` 最小割集恰为 `{A},{B}`；
   - 共享子门的事件归属（可选/无关）与共享门仅规范化一次；
   - 超限场景：`3^7=2187 > 2000` 报 `complexity_limit`，且边界 `2000` 完整输出；
   - 定量复核：重叠割集精确概率 `(A∧B)∨(B∧C)=0.375`（非互斥相加）、逐事件条件概率与一致性；
   - 旧的仅标识格式与非法/越界/七位小数概率只阻止定量、不影响定性；
   - 概率 `0`/`1` 边界与六位小数精度（`0.000003999997` 精确值）；
   - `quantitative_limit`：保留 78 个定性割集且无任何概率，概率全改 0 后立即恢复；
4. HTTP 冒烟：对 `web` 服务的 `/healthz` 与 `/` 做就绪重试与内容断言。

全部通过退出码为 0 并自行退出；任一步失败退出码非零。

## 目录结构

```
src/core/
  types.ts        # 数据模型、结果状态与定量结果类型
  parser.ts       # 事件(含可选概率字段)/门/顶事件解析（保留非法行与行号）
  validate.ts     # 缺失引用、自引用、Tarjan 环检测、命名冲突
  engine.ts       # 位掩码割集展开、吸收律消超集、每门 2000 上限、事件归属
  probability.ts  # BigInt 精确有理算术、Shannon 分解、逐事件条件概率、200000 状态预算
  pipeline.ts     # 解析 → 校验 → 分析 编排（auditDetailed 含字段信息，audit 兼容旧调用）
  *.test.ts       # 核心算法测试（41 项：定性 26 + 定量 15）
src/sample.ts     # 供电示例（仅标识 / 含概率）与定量上限压力示例
src/App.tsx       # 编辑器、问题定位、割集联动高亮、定量面板、超限警示 UI
src/App.test.tsx  # 页面交互测试（8 项：定性 3 + 定量 5）
scripts/          # verify 一次性服务脚本
nginx.conf        # 静态托管 + /healthz
Dockerfile        # deps / builder / verify / runtime 多目标
docker-compose.yml
```
